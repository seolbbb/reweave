## Finding and recheck

P2, resolved and rechecked: keyboard focus was lost after closing the evidence drawer. Reproduction: Explore, focus Open source message #0, press Enter, observe Close receives focus, Shift+Tab wraps to Jump #0, Tab wraps back, press Escape. The drawer closed but `document.activeElement` became BODY. The parent implemented an explicit opener capture before the awaited source load. Recheck on `index-BHiKcQft.js` repeated the native key sequence and returned focus to the exact source button, retaining its accessible name. See `browser-qa-focus-fixed.png` and the final focus observations in the transcript. No further product-blocking behavior was observed in the tested flows; download completion and actual browser zoom remain the explicit coverage limits below and in the results table.

## Download harness limitation

The browser tool reported `Download was canceled` for Graph PNG, an independent text Blob anchor whose URL was deliberately retained, and the diagnostics HTTP attachment. Ordinary clicks also created no files. All relevant product endpoints returned 200. Enabling downloads through CDP in this owned browser (without changing domain restrictions) did not resolve it. Therefore immediate object-URL revocation is not established as the cause, and this report does not claim that user-visible file saving succeeded.

To continue the restore and PNG checks, read-only instrumentation recorded the Blob objects passed to the original URL.createObjectURL function, preserving its behavior. The exact PNG bytes were decoded and inspected. The encrypted response bytes were saved only within the isolated QA directory and uploaded through the real file control. Diagnostics JSON was retained from the same Origin-guarded loopback endpoint. File saving in the packaged app remains a separate verification item.

The parent independently found a separate desktop launcher defect: pywebview defaults `ALLOW_DOWNLOADS` to false, and its EdgeChromium handler cancels downloads under that setting. The launcher now enables it before `create_window`, with a mocked native-launcher contract test. This addresses the observed desktop configuration defect; it does not explain or resolve the isolated headless-shell cancellation above. A real Windows Save dialog and completed packaged-app file save were not exercised by this QA run.
